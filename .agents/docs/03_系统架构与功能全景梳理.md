# OxideTerm 系统架构与功能全景梳理

本文档对 OxideTerm 项目的**核心功能全景**、**Rust 工作区代码分层**、**关键业务路径**以及**底层开发规范**进行系统性梳理，作为日常开发与特性扩展的指导手册。

---

## 1. 项目定位与核心设计哲学

OxideTerm 是一个基于 **纯 Rust** 与 **GPUI**（来自 Zed 的高性能 GPU 渲染引擎）构建的原生跨平台终端运维工作区。

### 核心设计哲学

1. **彻底摆脱 Web 技术栈**：
   - 无 Electron，无内置浏览器 WebView，界面全部通过 GPU 硬件加速管线（Windows DirectWrite/DirectX、macOS Metal、Linux Vulkan/Wayland）直接绘制，内存占用仅为传统客户端的 15%~25%。
2. **以“服务器节点 (Node)”为中心的一体化工作区**：
   - 彻底打破“终端是终端、SFTP 是独立工具、端口转发又是另一套界面”的碎片化模式。
   - 同一个服务器节点下，**终端命令行、双栏 SFTP、端口转发、远程轻量 IDE、主机指标监控**共享底层同一条物理连接通道。
3. **纯 Rust 网络协议栈**：
   - SSH 协议栈基于 `russh` + 硬件加速密码库实现，完全脱离 OpenSSL 和 libssh2 系统依赖，杜绝 C/C++ 动态库版本冲突。
4. **安全与隐私优先（Local-First & BYOK）**：
   - 零遥测，无账号体系，无云端中转；所有连接凭证均通过系统钥匙串（Windows DPAPI / Credential Manager）加密并进行内存零化（Zeroize）保护。
   - AI 助手（OxideSens）采用用户自备密钥（BYOK）模式，危险运维操作必须经过明确的用户交互审批。

### 2.1 终端虚拟化与多协议支持

- **协议覆盖**：本地 Shell (PowerShell/CMD/Bash)、SSH、Mosh (基于 fernomade 纯 Rust 实现)、Telnet、Serial 串口。
- **高级终端交互**：
  - **原生 `tmux -CC` 控制模式**：将远端 tmux 会话直接映射为本地 GPUI 拆分窗口，支持鼠标自由拖拽分屏。
  - **多目标广播群组**：支持给多个终端窗格同时广播输入命令。
  - **现代图形协议**：完整支持 Sixel 与 Kitty 图形协议，终端内可直接渲染查看图片。
  - **极速文件拖拽传输**：内置 `trzsz` 与 Zmodem 支持，在终端中直接拖拽文件即可触发高速收发。
  - **终端会话录制与回放**：兼容 asciicast 规范，支持本地端到端加密存储。

### 2.2 会话生命周期与连接多路复用 (NodeRouter)

- **多通道复用**：同一个目标主机的终端窗格、SFTP 文件树、端口转发链路共享同一个活跃物理连接。
- **优雅重连（Grace Period）**：发生网络轻微闪断时，系统进入 30 秒容错探活期，探活成功直接复原会话，防止远端 TUI（如 vim/htop）崩溃。
- **跳板机路由（Jump Host）**：支持无限级跳板链路串联，自动管理子通道生命周期。

### 2.3 文件管理与远程轻量 IDE

- **双栏 SFTP / FTP 管理器**：支持本地与远程文件对照、断点续传、带宽限速、后台传输队列、常用目录书签。
- **内置远程编辑器 (IDE 模式)**：
  - 基于 Tree-sitter 与 syntect 的高性能多语言语法高亮。
  - 原子写入与冲突检测机制，防止多人并发编辑或网络掉线时写坏远程文件。
  - 工作区会话持久化，关闭软件后重新打开可恢复已打开的代码标签页。

### 2.4 网络隧道与图形转发

- **端口转发**：本地端口转发 (`-L`)、远程端口转发 (`-R`)、动态 SOCKS5 代理 (`-D`)。
- **智能探测**：自动嗅探远程服务器上开启监听的端口，一键创建隧道映射。
- **X11 转发**：支持远端 Linux GUI 程序的本地渲染显示。

### 2.5 AI 助手 (OxideSens) 与 MCP 扩展

- **多模型支持**：内置对接 OpenAI、Anthropic Claude、Google Gemini、本地 Ollama 以及任何兼容 OpenAI 协议的第三方大模型。
- **安全审批沙箱**：AI 分析输出的运维脚本或指令，必须经由用户显式点击审批确认后方可送入终端执行。
- **MCP (Model Context Protocol)**：集成开源标准 MCP 客户端与服务端，允许 AI 调度本地及远程环境的工具链。

### 2.6 Wasm 插件系统

- **安全沙箱引擎**：基于 `wasmtime` 构建，插件运行在隔离的 WebAssembly 沙箱内。
- **开箱即用扩展**：支持通过插件市场动态安装 RDP 远程桌面、VNC 查看器等复杂原生能力。

    TermView --> TermCore[crates/oxideterm-terminal & alacritty-terminal]

    NodeRoute --> SshStack[crates/oxideterm-ssh & russh (纯Rust SSH)]

## 4. 关键业务路径与源码导航

在进入日常编码前，建议优先定位以下核心代码路径：

1. **应用总入口与主窗口挂载**：
   - 路径：`crates/oxideterm-gpui-app/src/main.rs`
   - 职责：解析命令行启动参数、单例进程检测、字体载入、拉起主工作区窗口。
2. **主工作区视图控制中心**：
   - 路径：`crates/oxideterm-gpui-app/src/workspace.rs`
   - 职责：管理侧边栏、标签页切换、树状窗格拆分、快捷键注册、弹层（Overlay/Modal）控制。
3. **连接注册表与节点路由 (NodeRouter)**：
   - 路径：`crates/oxideterm-connections/src/`
   - 职责：管理节点连接生命周期，处理多窗格对同一节点的复用与断线重连。
4. **共享 UI 组件库**：
   - 路径：`crates/oxideterm-gpui-ui/src/`
   - 职责：所有通用控件（按钮、文本框、复选框、下拉框、选项卡等）的唯一定义处。
5. **主题与设计令牌**：
   - 路径：`crates/oxideterm-theme/src/`
   - 职责：浅色/深色主题切换、背景色、文字色、边框色、圆角等全局令牌。

## 5. 核心架构约束与避坑准则 (System Invariants)

根据项目根目录 `AGENTS.md` 与 `docs/SYSTEM_INVARIANTS.md`，开发时必须遵循以下铁律：

### 5.1 弹层与焦点防击穿

- 弹层（Modal/Overlay）打开时必须**绝对独占键盘焦点**，禁止任何按键穿透到背后的终端窗格。
- 输入框粘贴操作必须精准写入当前焦点文本框，禁止泄漏为终端粘贴。

### 5.2 严禁散落手写 UI 样式与硬编码

- **严禁在业务页面中硬编码颜色（如 `#ffffff` 或 `rgb(...)`）**，必须使用 `theme.colors.*` 语义令牌。
- **严禁在业务页面中手写输入框或按钮**，必须统一复用 `oxideterm-gpui-ui` 中的标准控件。

### 5.3 会话所有权铁律

- SSH 物理连接的生命周期属于 `NodeRouter`，**绝不能由单个终端窗格隐式拥有**。
- 关闭终端窗格仅代表移除一个消费者，不得影响正在运行的 SFTP 上下传或端口转发。

### 5.4 敏感凭证内存安全

- 用户密码、私钥、Token、SSH Passphrase 临时存取时，优先使用具备自动内存零化能力的容器。
- 绝不能将用户密码或敏感凭据写入日常日志、调试输出或错误提示中。

### 5.5 国际化一致性

- 用户界面可见文案必须接入 `oxideterm-i18n` 机制，新增或修改文案需同步维护 11 个语言字典，禁止直接在 UI 逻辑中硬编码展示中文或英文。

## 6. 日常开发常用命令速查

针对当前系统硬件配置（16 逻辑处理器 / 48GB 物理内存）：

```powershell
# 1. 日常快速语法与类型检查（耗时 2~3 秒，最推荐）
cargo check -p oxideterm-gpui-app

# 2. 启动桌面客户端进行界面与功能调试（推荐 -j 10，兼顾极速与系统流畅）
cargo run -p oxideterm-gpui-app -j 10

# 3. 运行单个模块的单元测试
cargo test -p oxideterm-connections

# 4. 运行伴生命令行工具健康诊断
cargo run -p oxideterm-cli -- doctor

# 5. 编译正式发布包（经过最高等级优化与代码压缩）
cargo build --release -p oxideterm-gpui-app -j 10
```
